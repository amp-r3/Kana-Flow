# ADR 050: Prompts Completed at the End of a Test, and the Memory of a Long Test

- **Status:** In force. Amends [ADR 042](042-zen-test-and-finish-key.md) (what "completed" means when a zen test is finished by hand) and refines [ADR 036](036-session-factory-and-trainer.md) (memory of a long test).
- **Context:** A zen test ended by hand and a time test at its deadline counted the prompts that `committedPrompts()` returned. A prompt that ends in ん is not committed until the next key says whether the `n` was a whole ん, so typing `pan` in a zen test and pressing Ctrl+Enter threw the test away, and the last word of a longer test was lost from the result. A count test already ended on `isComplete()` and counted it. The live counter read `promptResults`, which holds settled prompts, so it could differ by one from what the result held. ADR 036 also claimed that the memory growth of a zen test was removed, but the session kept the time of every accepted keystroke without a bound and copied the whole result list for each prompt, which is quadratic over a long test.
- **Decision:**
  1. At the end of a zen test (by hand) and of a time test (deadline) the completed prompts are all those before the displayed one, whose results are recorded then. The displayed prompt moves on as soon as the live conversion reaches the end of the current one, so a prompt on ん typed with a single `n` is completed; the prompt being typed is not. Reaction times of tokens whose paths are still ambiguous are estimated by the existing rule in `flushResults`.
  2. `Session.completedPrompts` is a signal of that number, written when the displayed prompt changes (and set to the recorded count when a count test ends). The live counter reads it, so the counter equals the result.
  3. `promptResults` is a computed over a mutable list and a mark, so copying happens only when something reads it; the live line no longer does. The results still grow by one entry per prompt until the test ends: O(n) in memory, which is the cost of showing them at the end.
  4. `compact()` also drops the times of the keystrokes that no remaining token will ask for: from the last keystroke of the last dropped token, kept because the next token is timed from it. The session offsets keystroke indices by the number dropped.
- **Justification:** The user sees a word as done once the display has left it, so dropping it at Ctrl+Enter reads as lost work. The displayed prompt is a state the session already holds, and no change to the engine is needed. Alternatives rejected: counting the displayed prompt as well (it is partly typed in the middle of a prompt); changing `committedPrompts()` (the engine API is normative, and the live indicators and compaction depend on it); a ring buffer for results (the result screen needs all of them).
