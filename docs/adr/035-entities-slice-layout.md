# ADR 035: Entities Slice Layout

- **Status:** In force. Amends [ADR 011](011-state-division-and-storage-isolation-entities-kana-vs.md) and [ADR 015](015-merging-widgets-layer-into-pages-trainer-ui.md) for the layout only.
- **Context:** The P2 slice table in [Frontend](../spec/frontend.md) names `entities/prompt`, `stats` and `settings` and a `training` feature. The code had `entities/kana` (prompt pool, engine binding, content and the practice settings), `entities/progress`, `entities/session` and `features/type-prompt`. The test length lived in `entities/session` and was written to the same `kanaflow:settings:v1` key as the practice settings, each store merging in the other's part.
- **Decision:**
  - `entities/kana` becomes `entities/prompt` (pool, picker, engine binding, content, kana table); `entities/progress` becomes `entities/stats`; `features/type-prompt` becomes `features/training`. Identifiers inside them are unchanged.
  - New `entities/settings` owns the practice settings and `testConfig` and writes all six values in one record. The merge on write is gone. Storage keys and the saved format are unchanged, so no migration is needed (D18 stays in P3).
  - `entities/prompt` and `entities/settings` do not import each other. `prompt` takes `PoolSettings` (`script`, `content`, `rowIds`) as a plain argument; `settings` derives `ScriptMode` and `ContentKind` from `ValidSettings`; `DEFAULT_BASIC_ROWS` lives in `shared/lib`.
  - `setTestConfig` no longer resets the session, because `settings` cannot import `session`. `setupSettingsResetWatcher` already resets it when any of the six signals changes, so the behaviour of the page is unchanged. The test length is now written after the 300 ms debounce, like the other settings, and flushed on `pagehide`.
  - `entities/session` stays until `createSession()` replaces it.
  - Steiger's `fsd/inconsistent-naming` is switched off: the spec names the slices `prompt`, `session`, `settings`, `stats`, `learn`, `user`, and the rule would force one grammatical number on all of them.
- **Justification:** One owner per persisted record removes the cross-store merge and makes the later settings migration (P3) touch one module. Plain arguments keep sibling slices independent without a shared type layer. Alternatives rejected: keeping the settings in `prompt` (the settings screen of P5 and `/settings` would import a prompt slice); renaming the slices to a plural form (`prompts`, `sessions`) to satisfy the rule and departing from the spec names; passing the session reset into `setTestConfig` as a callback (hides the coupling the watcher already provides).
