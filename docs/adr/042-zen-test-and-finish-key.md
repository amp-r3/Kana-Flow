# ADR 042: The Zen Test and Its Finish Key

- **Status:** In force. Amends [ADR 022](022-key-intent-semantics-reveal-strictly-via-escape.md) for one key. Amended by [ADR 050](050-completed-prompts-at-test-end.md): "completed" is every prompt before the one on screen, not `committedPrompts()`.
- **Context:** The spec lists a zen test (no length, ended by hand) and the key Ctrl/Cmd+Enter that ends it, and the rule for what a test ended by hand keeps ([Metrics](../spec/metrics.md), "Test end"). ADR 022 left every modifier combination to the browser.
- **Decision:**
  - **The config.** `{ kind: 'zen' }` joins `ValidTestConfig` and `isTestConfig`. It adds a case and changes none: settings saved with a time or count test stay valid (a test covers this), so no migration is needed, and the P3 migration moves `test` as it is.
  - **No timer, no limit.** A zen test arms no deadline and the stream has no end, like a time test without the clock. The live line shows the number of completed prompts.
  - **Ending it.** `Session.finish()` (the Finish button, and the `finish` intent from Ctrl/Cmd+Enter) ends only a running zen test; in any other test, or before the first key, it does nothing. A test with a completed prompt and time behind it becomes a result. Otherwise it is dropped like a restart, with no results screen: the session calls `onDiscard`, which the trainer sets to `restart()` (without it the session resets itself). "Completed" is the engine's `committedPrompts()`, as at a deadline, so a prompt whose final ん is still undecided does not count until the next key; "time" is from the first key to the finish.
  - **The key.** `classifyKeyDown` answers `finish` for Ctrl or Cmd with Enter, without Alt (AltGr is Ctrl+Alt on Windows) and outside a composition. The input source passes it and cancels it, but, as for every key, not with a dialog open or focus in another text field. Every other modifier combination is still ignored and not cancelled.
  - **The button.** Shown in a zen test only, after Restart in the DOM, so the first Tab still reaches Restart. It starts disabled and is enabled through the DOM by a signal effect when the test runs, so the first key does not render the screen. The effect reads the phase before it looks at the button: it would otherwise have no dependency while the button does not exist, and never run again. It shows the shortcut, `⌘ + enter` on Apple devices.
  - **The selector.** The test type has three values, and zen has no length group.
- **Justification:** An unplanned end needs a rule for what to keep, and the spec's is the smallest: a test with nothing to show should not leave an empty result. Resolving it in the session keeps the rule next to the state it reads. Alternatives rejected: counting the displayed prompt as completed when the user ends the test (the engine does not know yet whether its ん is final, and a deadline already follows the committed rule); a Finish key that works in every test (it would end a timed test early with a different meaning); a dedicated config field instead of a new `kind` (every `switch` on the kind would miss it).
- **Not here:** the idle end (5 seconds, zen exempt) and the hidden tab end are part of the metrics work; the `endReason` and the results screen for a manual end come with it.
