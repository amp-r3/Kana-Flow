# ADR 041: The Test Screen on the Text Stream

- **Status:** In force. Completes [ADR 040](040-text-stream-window-and-dom-writer.md) and the stream part of [ADR 031](031-adopt-the-nekotype-design-system.md).
- **Context:** The model and the writer of the stream existed but the screen still showed one prompt, a mirror of the typed romaji and a shake. The hot path (D16) allows no component render on a keystroke and one on a completed prompt, and the first key changes the phase of the session.
- **Decision:**
  - **One render per completed prompt.** `TextStream` reads `session.stream` and renders its tokens; it has no child component, so one render is one component render. Everything a keystroke changes goes around the render: the lines of text (counter, kana per minute, accuracy, notices, the revealed romaji, the translation, the prompt text) are signals passed as text nodes; the caret, buffer, token classes and the flash go through the writer by signal effects; the attributes tests read (`data-phase`, `data-canonical`, `data-rejected`) are written to the root. `data-rejected` is set by a rejected key and cleared by the next accepted one, so it does not depend on a timer.
  - **The page does not render when a test starts.** It switches to the results on a computed `finished`, which does not change from idle to running. The test counts every component render of the page from the first key, with a 45-prompt run that goes through `compact()`.
  - **The interface steps aside by one attribute.** `useTestChrome` sets `data-testing` on the document while a test runs; the stylesheet fades everything marked `data-chrome` out and then sets `visibility: hidden`, which takes it out of the tab order, so the first Tab reaches Restart. The elements keep their place, so nothing moves. A mouse movement of more than 8 px shows them until the next key.
  - **Restart** has the class `nk-on-focus`: invisible until focused, always visible on a touch screen (`pointer: coarse`), as a phone has no Tab. It stays focusable and is not removed from the layout.
  - **Notices** live in one reserved line that exists from the start; the revealed romaji is a second element in it, so its font can differ without a render. The translation reserves two lines (the design's rule; the spec said one, and the text would jump on a narrow screen).
  - **Removed:** the mirror of the typed romaji, the shake and its timer, `typedBuffer`, `isShaking`, `activeTokenIdx`, the strictness label of the live strip (ADR 031). The old `live-kpm` e2e check for "started" is `data-phase`.
  - **The kana font is preloaded** in `index.html`; Vite rewrites the path to the hashed file. `check-budget.mjs` fails when the preload is missing, names a file that is not in `dist`, or lacks `crossorigin` (a font is fetched in CORS mode, so without it the file is requested twice).
  - **The stream is a picture:** it is `aria-hidden`; the prompt on display is a visually hidden element for assistive technology.
- **Justification:** A render at every key would redo about a hundred tokens; a few text nodes and class writes cost nothing, and they are the same four kinds of write in every case, so the budget is a property of the structure, not of care. Hiding by an attribute on the document reaches elements outside the page without a store or a context. Alternatives rejected: hiding the navigation from the page with state (renders at the first key, and the shell would need the session); `display: none` for the hidden interface (the text would move); removing Restart from view on a touch screen (no way to restart without a keyboard).
- **Consequences:** Initial JS is 32.94 KB gzip of 35, leaving about 2 KB for the zen test; the results screen (the largest lazy candidate) can be made a lazy chunk if the next changes need it.
