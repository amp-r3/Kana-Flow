# ADR 051: Input Source: Held IME Letters, Auto-repeat and Ctrl/Cmd+Enter

- **Status:** In force. Amends [ADR 038](038-hybrid-input-source.md).
- **Context:** Review of the input source found four gaps. (1) With a Japanese IME on, the first Latin letter of a word reaches the field as composition text before it becomes kana, and it was passed to the session: the test started and the letter counted as a mistake, although the notice promised that nothing is typed. (2) The notice was not hidden by Latin composition, so on a keyboard that composes everything (Gboard) it stayed after the user switched back to Latin. (3) Ctrl/Cmd+Enter was cancelled and the focus moved to the field before the session knew it had nothing to finish, which broke "open in a new tab" on a link. (4) A held key was input, so holding a wrong key piled up mistakes.
- **Decision:**
  - **Held letters.** Latin text of a composition is queued until there is proof that the IME is off. Proof is a latin vowel in a composition (an IME that is on turns it into kana), the end of a composition without kana, or a key typed directly. A consonant proves nothing and waits. Once proven, later letters go straight through, for as long as the input source is bound. Kana drop the queue and reset the proof, so the next word waits again. The queue is released in order, ahead of the vowel that released it.
  - **The notice.** A latin vowel in a composition hides it, because the IME that raised it would have converted that vowel. A consonant does not.
  - **Ctrl/Cmd+Enter.** `InputSourceDeps.canFinish` (the session's `canFinish()`: a zen test that is running) is asked before the event is cancelled. When it says no, the key is left alone and the focus does not move.
  - **Auto-repeat.** A `keydown` with `repeat` set that the source would otherwise take is cancelled and goes no further: it is not a keystroke, so it is not counted and does not reset the idle timer.
- **Justification:** The first consonant of a Gboard word cannot be told from the placeholder of an IME that is on, so the choice is between a wrong first keystroke and a short delay; the delay lasts until the next letter of the same word and costs one keystroke of latency once. Doing the check in the source keeps the session unaware of composition (ADR 038). Alternatives rejected: ignoring the first letter of every composition (loses a real keystroke on Gboard); detecting the IME from `keydown.key === 'Process'` (mobile keyboards do not send it).
- **Open:** the Android (Gboard) and iOS checks of ADR 038 are made on the preview of the PR that introduced this one: typing words, the lag in the first symbol only, no duplicates, the notice clearing when the layout is switched.
