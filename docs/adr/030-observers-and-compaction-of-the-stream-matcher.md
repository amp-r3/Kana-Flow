# ADR 030: Observers and Compaction of the Stream Matcher

- **Status:** In force.
- **Context:** [ADR 029](029-stream-engine-with-spelling-constraints.md) fixed the matcher model. Implementing the observers of [Input engine rules](../spec/engine.md) (`view`, `errorTarget`, `committedTimings`, `compact`) and wiring them into `TypingController` raised questions the spec left open.
- **Decision:**
  - **Paths.** Every position carries the keystroke range of its current token and a shared, immutable list of the tokens completed before it. Keystroke indices count accepted keys only; `MatchState` carries the count. When two paths reach the same position the first one in table order is kept, so memory stays bounded and the result is deterministic.
  - **Timings.** `committedTimings` reports a token only when every active position agrees on its keystrokes. `compact` drops only prompts that are committed and whose tokens are all agreed; a prompt whose last ん is still undecided waits one key. A 1,000-prompt run lost three timings before this rule.
  - **Results.** `TypingController` records a prompt when it is committed and its timings are agreed, with `endedAt` the time of the keystroke that committed it. At the end of a test it records the rest and estimates a token whose paths are still ambiguous as ending at the last key.
  - **`extend` and dead spellings.** A bare `n` that the appended context rules out keeps its spelling index with an empty set of continuations, and no new position may start in it. Old states stay valid and the stale position dies on the next key.
  - **`compact` and start positions.** A position that had completed a dropped token becomes a start position with no constraint. Only the bare `n` of ん constrains what follows, and a bare `n` always has the in-progress `nn` beside it, which blocks compaction until the next key; if a hand-made state breaks this, `compact` drops nothing.
  - **Display.** The controller shows the prompt that contains `view().displayedTokens`, never moves back, and keeps the displayed prompt and two more in the window.
- **Justification:** Shared path lists give exact per-token timing without enumerating readings, and the agreement rule keeps the "a ん resolved by the next prompt's first key is not inflated" requirement of [Metrics](../spec/metrics.md) without a second pass over the keystrokes. Alternatives rejected: keeping every path of a merged position (unbounded growth, no consumer for the extra data); carrying the spelling constraint across `compact` (unreachable); dropping a token with ambiguous timing (loses statistics).
