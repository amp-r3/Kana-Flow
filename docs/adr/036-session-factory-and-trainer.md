# ADR 036: Session Factory and Trainer

- **Status:** In force. Amends [ADR 020](020-readonlysignal-export-pattern-for-store-state.md): session state is exported as `ReadonlySignal` from an instance, not from a module. Refined by [ADR 049](049-session-boundaries.md): statistics are injected, the config is read when a prompt is loaded.
- **Context:** D17 asks for sessions created by a factory, so speed and learning sessions do not share state. The code had `TypingController` (a class) plus the singletons of `entities/session` (`phase`, `metrics`, keystroke counters, the test config). Every keystroke copied the whole keystroke array into a signal. The trainer page also picked prompts, loaded vocabulary and created the clock, scheduler and `Rng` itself, which kept that logic out of reach of tests that do not render.
- **Decision:**
  - `createSession({ nextPrompt, config, clock?, scheduler? })` in `features/training` replaces the controller and `entities/session`, which is removed. A session owns its phase, results, counters and metrics. The test length comes in as a function, read when a test starts. Session types and `computeMetrics` move to `features/training`: the spec lists no session entity.
  - Keystrokes are counted, not stored: `KeyTally` holds the accepted and rejected totals, the time of the first and last key and the accepted keys per second, so a keystroke is O(1). The per-second KPM series is computed from it with the same boundary rule as before (a key exactly one second after the first belongs to that second). The raw keystroke log is never kept, as the spec requires.
  - Live indicators: `liveKpm` and `liveAccuracy` count the non-skip tokens before `view().activeToken`, which every active position has passed, once each (a pointer into the matcher, rebased by `compact()`). Accuracy is committed tokens without an error over committed tokens. KPM is 0 for the first second of a test, so the first keys do not show noise. The ticker writes `tickerNow` on every accepted key as well as every second, so KPM does not wait for the next tick.
  - `createTrainer(deps?)` composes one session with the prompt source and the vocabulary loading and exposes `isLoadingContent`, `contentLoadFailed`, `noKanaForRows`, `restart()` and `start()`. The page keeps only presentation state. The watcher only calls its callback; the trainer passes `restart`, which resets the session itself.
  - The trainer starts in a layout effect: the first frame already shows a prompt, and unmounting stops it at once (a normal effect is cleaned up after the next paint, which let a stopped trainer react to a settings change in tests).
  - The live strip shows KPM and kana accuracy (spec D12, metrics.md). The results screen still shows the baseline WPM until P3 replaces it.
- **Justification:** A factory makes the state of a session an argument of the code that uses it, so tests build as many as they need and the learning session can reuse the same shape. Counting instead of storing removes the O(n) copy from the hot path and the memory growth of a zen test. Moving prompt selection and loading into a model puts the behaviour the e2e tests cover under unit tests. Alternatives rejected: keeping the class and the singletons behind a thin factory (the singletons are the shared state); computing live KPM from `committedTimings()` on every key (a pass over all tokens per key); an engine function for committed tokens (the view already gives the boundary, and the engine stays unchanged).
