# ADR 049: Session Boundaries: Injected Statistics, Config Read Once, Private Finish

- **Status:** In force. Refines [ADR 036](036-session-factory-and-trainer.md): its session factory now takes the statistics as a dependency, and the test config is read when a prompt is loaded, not on every use.
- **Context:** ADR 036 and `architecture.md` say a session gets its storage injected and shares no state (D17). `session.ts` imported `recordTokenOutcomes` and `flushProgress` from `entities/stats` and wrote to the global store itself, so two sessions shared one store; a learning session (P5) must not change the speed statistics. The comment on `Session.config` said the config is read when a test starts, but `promptLimit()` and `finish()` read it on every call, which only the settings watcher (it restarts the session on any change) hid. `finishSession()` was public, unused outside the session, and from `idle` moved the session to `finished`. `loadPrompt()` without `reset()` kept the old stream, because `shouldPublish` saw nothing to publish. Some API had no consumer: `mistakeCount`, `toggleWeakFocus`, the `dialog.contentDisabled` branch.
- **Decision:**
  1. `SessionDeps.stats` is `{ record(outcomes), flush() }`, a no-op by default. `session.ts` no longer imports `entities/stats`; `createTrainer` passes `recordTokenOutcomes` and `flushProgress`.
  2. The test config is read once, in `loadPrompt`, and the test runs by that snapshot (deadline, prompt limit, zen finish). A change of setting still restarts the session through the watcher.
  3. `finishSession` is private and does nothing unless the phase is `running`. `loadPrompt` always publishes a new stream.
  4. Removed: `Session.mistakeCount` (and the Esc counter before the first key), `toggleWeakFocus`, the unreachable `isContentDisabled` branch of the rows dialog with its `dialog.contentDisabled` strings. The settings watcher reads its six signals explicitly instead of through an array that was only measured.
- **Justification:** Statistics as a dependency makes the session a function of its arguments, as D17 asks, and costs one object. A snapshot of the config makes the comment true without relying on a watcher. Alternatives rejected: leaving the import and mocking the store in tests (the sharing stays); a callback per outcome batch with no `flush` (the debounced save must still be forced at the end of a test).
