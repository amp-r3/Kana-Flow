# ADR 048: Worst-Keystroke Latency Gate on Every Content Kind

- **Status:** In force. Corrects [ADR 043](043-keystroke-latency-gate-and-stepwise-publishing.md), which said stepwise publishing "removes the dominant cost".
- **Context:** Stepwise publishing did not remove the cost of a redraw of the text stream, it gathered it into a few keystrokes (about one in sixty). Measured at 4× CPU throttling before this change: a redraw cost 12–19 ms of work and one frame went past 33 ms, while the p95 was 1.3–2.8 ms, because fewer than 5% of the keys are redraws. The gate looked only at the p95, so a redraw could become arbitrarily slow without a failure. It also ran only on the default settings (Single Kana), not on Words or Phrases, and relied on the default 30 s test length without checking that the test was still running.
- **Decision:**
  1. **Three kinds of content.** The test runs for Single Kana, Words and Phrases, 3 runs of 200 keys each, with the settings written to `localStorage` before the page loads (hiragana, learner, the default rows, a 120 s timed test).
  2. **A ceiling on the worst keystroke.** Besides the median of the three p95 values against the budgets (8 ms of work, two frames), the median of the three maxima must stay within 25 ms of work and 50 ms to the next frame. The ceiling is the median of the runs, so a single noisy run does not fail the gate, but a redraw that is slow in every run does.
  3. **The test must still be running.** After the keys the arena has to be in the `running` phase, with a message that says so; otherwise the numbers would include a results screen.
  4. **Not to be loosened.** When a measurement fails a ceiling, the cause is found and discussed, as for the other budgets.
- **Justification:** The ceilings sit above what the redraw costs now (work 12–18 ms, frame 25–37 ms in the measurements below), and below what a user would notice as a hitch. Checking the maximum is the only way to see a cost that is paid rarely. A slowed redraw (12 ms of busy work in the writer's `sync`) fails the gate on the work ceiling while the p95 stays at 1.6 ms.
- **Consequences:** `verify` is longer by about two minutes. At the time of this change, per content (median of three worst keystrokes): Single Kana work 18.2 ms, frame 35.3 ms; Words 13.5 and 28.3 ms; Phrases 15.8 and 36.4 ms; the p95 values stay at 1.4–2.0 ms of work and 22.6–24.3 ms to the frame. A single run can reach 49.5 ms for a frame, close to the ceiling; on a noisy CI runner this is where the gate fails first.
